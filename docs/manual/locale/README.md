# Manual translations

Korean catalogues for the Sphinx manual, maintained with `sphinx-intl`.

## Updating

```bash
cd docs/manual
make gettext                                  # extract into _build/gettext
sphinx-intl update -p _build/gettext -l ko    # merge into locale/ko/
# edit locale/ko/LC_MESSAGES/*.po
sphinx-build -b html -D language=ko . _build/html/ko
```

Existing translations survive an update; new and changed strings appear with an
empty `msgstr`, and a changed source marks the old translation fuzzy rather than
dropping it.

## What is deliberately not translated

Two catalogues are left empty on purpose, and Sphinx falls back to the English
source for them:

- **`api.po`** — the API reference is generated by autodoc from docstrings in
  `core/`. Translating it would put a Korean description beside English source
  code, and the two would drift apart the moment a docstring changed. Readers
  of an API reference are reading the code as well.
- **`changelog.po`** — the changelog is the release record. It is quoted in the
  GitHub releases and in the tag messages, and those are one text in one
  language; a translated second copy would be a second source of truth for what
  shipped.

Everything a user or a contributor reads — installation, hardware, the capture
workflow, configuration, troubleshooting, architecture and the developer
guide — is translated in full.
