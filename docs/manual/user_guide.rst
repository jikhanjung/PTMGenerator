User guide
==========

Workflow
--------

1. **Configure** (:menuselection:`Edit --> Preferences`)

   Choose the controller's serial port, set the path to ``PTMfitter.exe``, and
   check the LED count. See :doc:`configuration` for every setting.

2. **Open the working directory** (:menuselection:`File --> Open Directory`)

   Choose the folder your tethering software writes photos into. If it already
   contains an ``image_data.csv`` the previous capture table is loaded;
   otherwise the directory is scanned and a table is rebuilt from the files
   found there.

   **The folder you pick is watched, not assumed.** Canon's EOS Utility — and
   most tethering software — files images into a dated subfolder that does not
   exist until the day's first shot, so at the moment you start a session the
   only folder you can pick is the parent. Everything beneath it is searched
   until a shot arrives; whichever folder that shot lands in becomes the
   working folder for the run, and ``image_data.csv`` is written there. The
   directory field updates to show it.

   Once the folder is known the search narrows to it, so a root holding a
   season of dated folders costs nothing per poll.

3. **Test Shot**

   Fires a single frame. Use it to check the camera, the exposure and the serial
   link before committing to a full run.

4. **Take All Pictures**

   Runs the full sequence. **Pause/Continue** and **Stop** control the run while
   it is in progress.

5. **Review**

   Select a row to preview that image. Uncheck any shot you do not want in the
   final PTM. **Retake Picture** re-shoots the selected rows.

6. **Generate PTM**

   Writes the ``.lp`` file beside the images and runs PTMfitter. You are
   prompted for the output ``.ptm`` path.

What a run does per LED
-----------------------

.. code-block:: text

   send <SHOOT,n>          light the LED and fire the shutter
   wait 2 ticks            let the camera write the file
   poll for up to 5 ticks  look for a file newer than the last one accepted
     found    -> record it, move to the next LED
     not found-> retake, up to Retry Count times
                 then record the slot as missing and move on

One tick is one second.

Missing shots
-------------

A shot that never arrives is recorded with ``-`` for its filename. The slot is
kept rather than removed, so the remaining images keep their original LED
indices and still get the right light vector. A run with gaps still produces a
valid PTM — just from fewer images.

Use **Retake Picture** on those rows to fill them in.

Running without the controller
------------------------------

Starting a capture with no serial port configured asks whether to continue.
Cancelling is the default, because without the controller the LEDs and shutter
are never triggered and every slot times out. Continuing anyway is there for
trying the interface out with no hardware attached.

Files a run produces
--------------------

===========================  =============================================
``image_data.csv``           The capture table: index, directory, filename,
                             included. Written into the capture directory
``<dirname>.lp``             Light positions, generated by **Generate PTM**
``<chosen name>.ptm``        The output, produced by PTMfitter
``output.log``               Console output, next to the executable
===========================  =============================================
