# Making mypy actually check `ui/`

2026-07-28. `check_untyped_defs` was off for `ui/`, and three documents said
mypy gated over it when nothing ran it there at all.

## What "checked" meant before

    Makefile               mypy --config-file pyproject.toml core/
    .github/test.yml       mypy --config-file pyproject.toml core/
    .pre-commit-config     files: '^core/.*\.py$'

`mypy ui/` did pass if you ran it by hand, which is what made the claim look
true. Two things were wrong with that. Nothing ran it, so it could not gate. And
`check_untyped_defs` was explicitly `false` for `ui.*`, so mypy skips the
*bodies* of unannotated functions — and this code carries few annotations, so a
clean run meant almost nothing had been examined.

Turning it on: **100 errors**. The point of this entry is that they were four
causes, not 100 mistakes, and that none of them was waived.

## 1. Attributes bolted onto QApplication (31)

The entry point did this:

```python
app = QApplication(argv)
app.translator = None
app.language = "en"
app.settings = open_preferences()
```

and both windows read them back off `QApplication.instance()`. Nothing declares
them, so no stub knows they exist — and `read_settings()` depending on
attributes the entry point happened to have set was a genuine fragility, not
just a typing complaint. A window built by a script got an `AttributeError`.

`ui/app.py` declares them on a `PtmApplication(QApplication)` subclass with
defaults in `__init__`. The `app()` helper casts `QApplication.instance()` to it
— honestly Optional, but a widget cannot exist without an application, so every
caller would otherwise be guarding a case that cannot arise.

`PtmApplication.preferences()` came out of the same change: both windows carried
the same "if it is None, open one" guard, and every use after it still read as
possibly-None. One method, non-Optional return, guard gone from both.

## 2. Attributes shadowing Qt methods (23)

```python
self.statusBar = QStatusBar()  # shadows QMainWindow.statusBar()
self.layout = QFormLayout()  # shadows QWidget.layout()
self.parent = parent  # shadows QWidget.parent()
```

mypy reports these as `"Callable[[], QStatusBar | None]" has no attribute
"showMessage"` — it resolves the name to the inherited *method*, because that is
what the class declares. At runtime the instance attribute wins, so it works;
but `self.statusBar()` would now raise `TypeError`, and the method is gone for
anyone who wanted it.

Renamed to `status_bar` and `form_layout`. `self.parent` was never read and
`QWidget` already keeps what `__init__` was given, so it was deleted.

**This is not the Qt-mirroring naming `CLAUDE.md` protects.** `btnOkay`,
`edtPtmFitter` and `Okay` mirror Qt's style and shadow nothing. These three
shadowed real inherited methods, which is a hazard rather than a convention.

## 3. Qt accessors that are Optional (30)

`menuBar()`, `horizontalHeader()`, `selectionModel()` and `addMenu()` are all
declared as returning an Optional, and that is honest — a `QTableView` with no
model genuinely has no selection model. In `setup_ui` they cannot be None: the
widget was just constructed and the model just set.

`ui/app.py`'s `require(value, what)` checks and returns the value typed. Written
as a check rather than a `cast` so that a violated assumption names which
accessor failed, instead of surfacing as `AttributeError: 'NoneType' object has
no attribute ...` several frames away.

## 4. Unscoped enum access (8)

`Qt.Checked` etc. The PyQt5 stubs declare them under their scoped enums —
`Qt.CheckState.Checked` — and the scoped spelling is identical at runtime, which
a quick check confirmed before touching 8 call sites.

## The one waiver that was considered and rejected

A class-level `statusBar: QStatusBar  # type: ignore[assignment]` would have
silenced 23 findings with one line instead of renaming. The config comment this
entry replaces already argued against exactly that: it hides a hazard rather
than removing it, and the whole reason for turning the setting on was to stop
"clean" meaning "not looked at".

## State

`core/` and `ui/` both checked, both with `check_untyped_defs`, in the Makefile,
CI and pre-commit. 347 tests, ruff clean.
