# Translating the manual

## Date: 2026-07-28

The application interface has been fully Korean for a while — 47 strings — while
the manual was English only. Closing that was the last open item from the R01
audit's follow-up list besides `check_untyped_defs` for `ui/`.

## Nothing needed setting up

`sphinx-intl` was already in the docs extra, and `conf.py` already had
`locale_dirs = ["locale/"]` and `gettext_compact = False` from when the manual
was written. The catalogues had simply never been generated.

    make gettext
    sphinx-intl update -p _build/gettext -l ko

304 strings across ten catalogues.

## What was not translated, and why

180 of the 304 were translated: the eight pages a user or a contributor reads.
Two catalogues were deliberately left empty, and Sphinx falls back to English
for them. Both arguments are written down in `docs/manual/locale/README.md`,
because "untranslated" and "deliberately not translated" look identical to
whoever comes next:

- **`api.po` (84 strings)** — generated by autodoc from docstrings in `core/`.
  Translating it puts a Korean description beside English source code, and the
  two diverge the moment a docstring changes. Nobody reads an API reference
  without reading the code.
- **`changelog.po` (40)** — the changelog is the release record, quoted verbatim
  into tag messages and GitHub releases. A translated second copy is a second
  answer to "what shipped".

That is 124 strings not translated, which is not a shortfall so much as a
boundary: translate what is read as prose, not what is generated from something
else that stays in English.

## The switcher

Modan2's pattern, in `_templates/layout.html`: swap the language segment of the
current URL rather than linking to the other index, so switching keeps the
reader on the page they were reading. Two additions:

- a fallback for being served without a language segment, which is what a local
  `make html` produces;
- on a narrow screen it goes back into the document flow, because fixed at
  top-right it sits exactly on top of the RTD theme's mobile nav button.

## What the translation caught

The Korean build failed under `-W`:

```
developer_guide.rst:59:<translated>:1: WARNING: Inline strong start-string
without end-string.
```

`**강조** 되어` — a `**` run followed immediately by a Hangul particle. docutils
needs a word boundary after the closing `**`, and a Hangul character is not one,
so the emphasis never closes and the literal asterisks render. This cannot
happen in English, where a closing `**` is followed by a space or punctuation.

Rewritten so the emphasis closes before the particle. Worth recording because
the class of bug is specific to agglutinative languages and will recur: any
translated `**...**` immediately followed by 은/는/이/가/을/를/에/의 is suspect.

The other warning was `locale/README.md` being picked up as an orphan document;
`locale` is catalogue data, not part of the document tree, and is excluded now.

**Building translations with `-W` is the point.** A translation that breaks
markup renders wrong rather than failing, and nobody reading the English site
would ever see it.

## Publishing

Each language builds into its own directory with a redirect at the site root:

    /            → en/index.html, with both links visible
    /en/...      English
    /ko/...      한국어

`make docs` does the same locally, so the local layout and the published one
cannot diverge — the switcher's URL rewriting depends on that layout.

Live at <https://jikhanjung.github.io/PTMGenerator/ko/>.
